## 1. Fixed Auth Context 404 Redirect Bug

### Problem

The authentication system was redirecting users to the login page whenever a 404 error occurred, even for valid authenticated users. This happened when navigating to non-existent product pages or any missing resource.

### Root Cause

In `apps/client/hooks/use-authenticated-api.ts`, the error handling logic was checking for `error.status === 401` but:

- Not checking the `error.statusCode` property (which is what the API actually returns)
- Not excluding 404 errors from the redirect logic

### Solution

Updated the error handling in `use-authenticated-api.ts`:

```typescript
// Before:
if (error.message === "Authentication failed" || error.status === 401) {
  await logout();
  router.replace("/login");
}

// After:
const statusCode = error.statusCode || error.status;
if (
  error.message === "Authentication failed" ||
  statusCode === 401 ||
  statusCode === 403
) {
  await logout();
  router.replace("/login");
}
```

**Now only 401 (Unauthorized) and 403 (Forbidden) errors trigger logout and redirect. 404 errors are handled gracefully.**

## 2. Fixed Prisma Database Connection Error

### Problem

Server was failing to start with error:

```
PrismaClientConstructorValidationError: Invalid value undefined for datasource "db"
```

### Root Cause

`PrismaService` was always passing a datasource configuration to `PrismaClient`, even when `DATABASE_URL` environment variable was undefined. Prisma's constructor validation rejects `undefined` values.

### Solution

Updated `apps/server/src/prisma/prisma.service.ts` to conditionally pass datasource:

- If `DATABASE_URL` or `DATABASE_URL_POOLED` exists → pass explicit datasource config
- If neither exists → call `super()` without config, let Prisma use schema defaults
- Added warning log when no database URL is provided

### Additional Improvements

- Created `.env.example` file in `apps/server/` with all required environment variables
- Documented the database URL format and optional pooled connection

## Setup Instructions for New Developers

1. **Set up database environment variables:**

   ```bash
   cd apps/server
   cp .env.example .env
   # Edit .env and add your actual PostgreSQL connection string
   ```

2. **Run database migrations:**

   ```bash
   cd apps/server
   npm run prisma:migrate
   npm run prisma:generate
   ```

3. **Start the development servers:**

   ```bash
   # Terminal 1 - Backend
   cd apps/server
   npm run start:dev

   # Terminal 2 - Frontend
   cd apps/client
   npm run dev
   ```
